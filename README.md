# Volatoo RFCs

Cross-repository proposals and long-lived project decisions.

## Belongs here

- changes spanning two or more repositories or trust boundaries;
- compatibility contracts and staged migrations;
- project-wide support, deprecation, and governance policy;
- decisions whose alternatives must remain discoverable after implementation.

Component-local design documents stay beside the code they version. An RFC is
not a substitute for implementation documentation or a roadmap issue.

Accepted RFCs will record status, owners, affected repositories, compatibility
impact, rollout gates, and superseding decisions. The repository remains a
scaffold until the first cross-repository proposal is submitted.
